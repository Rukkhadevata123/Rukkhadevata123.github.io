    用 clang-cl、vcpkg 和 CMake Presets 配置 Windows C++ 工程

    之前在 Linux 开发镜像里配置过编译器和大型依赖。这次回到 Windows，用一个使用 import std; 和 import vulkan; 的 C++23 起步程序检查 OCCT、SDL3、Dear ImGui 和 Vulkan 的头文件版本，再用 Slang 编译一个三角形顶点着色器。Podman 和 Dev Containers 配置记录

    这个工程有两处要选编译器。CMake preset 负责主程序，vcpkg 的 triplet 负责需要从源码构建的依赖。我给两边都选了 clang-cl.exe，生成 Release 版本。终端和 VS Code 共用 build-release，clangd 也从这里读取编译参数。

    1 准备 Windows 工具链 #

    1.1 安装基础工具 #

    编译器、构建工具和包管理器都采用独立安装，避免和 Visual Studio 内置版本混在一起：

    powershell
    winget install --id LLVM.LLVM --exact --source winget
winget install --id Kitware.CMake --exact --source winget
winget install --id Ninja-build.Ninja --exact --source winget
    • LLVM 23.1.6 默认装在 C:\Program Files\LLVM\bin，包含 clang-cl、clangd、clang-tidy 和 clang-format。
    • CMake 4.5.1 默认装在 C:\Program Files\CMake\bin。CMake 4.5 原生支持 C++23 的 import std;，不需要再配旧版的实验性开关。
    • Ninja 1.13.2 负责并行构建和 C++ 模块依赖扫描。

    Windows 上的 clang-cl 接受 MSVC 风格的参数，编译和链接还需要微软的 C++ 标准库（含 std.ixx 模块文件）、CRT 以及 Windows SDK。在 Visual Studio Installer 中安装 Visual Studio Build Tools 2026（或完整版 Visual Studio），勾选「使用 C++ 的桌面开发」下的 MSVC x64/x86 工具集与 Windows SDK（本文对应 MSVC 14.52 与 Windows SDK 10.0.26100.0）即可，不需要勾选 VS 自带的 CMake、LLVM 和 vcpkg。Clang 的 Windows 使用说明

    vcpkg 直接单独克隆到固定目录（例如 D:\vcpkg）并完成 bootstrap，不需要加入全局 PATH 或系统环境变量，路径和缓存目录统一在后面的 CMakeUserPresets.json 里指定：

    powershell
    git clone https://github.com/microsoft/vcpkg.git D:\vcpkg
D:\vcpkg\bootstrap-vcpkg.bat -disableMetrics

    其他来源说明：如果更希望统一由 Visual Studio Installer 管理工具，也可以在「单个组件」里勾选 VS 自带的 CMake、C++ Clang tools for Windows 或 vcpkg，只需把对应的路径排在 PATH 前面，并将 VCPKG_ROOT 指向 VS 安装目录下的 VC\vcpkg。

    1.2 初始化 x64 开发环境 #

    在准备运行 CMake 的 PowerShell 里执行以下命令。vswhere 找到 Visual Studio Build Tools，Enter-VsDevShell 注入 MSVC 头文件、标准库模块源文件路径、Windows SDK 和链接器环境。

    powershell
    $vswhere = Join-Path ${env:ProgramFiles(x86)} 'Microsoft Visual Studio\Installer\vswhere.exe'
$vsRoot = & $vswhere -latest -products '*' -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
Import-Module (Join-Path $vsRoot 'Common7\Tools\Microsoft.VisualStudio.DevShell.dll')
Enter-VsDevShell -VsInstallPath $vsRoot -SkipAutomaticLocation -DevCmdArguments '-arch=x64 -host_arch=x64'

$llvmBin = Join-Path $env:ProgramFiles 'LLVM\bin'
$env:Path = "$llvmBin;$env:Path"

Get-Command clang-cl, clangd, cmake, ninja | Select-Object Name, Source
clang-cl --version
cmake --version
ninja --version

    先初始化 VS 开发者环境，再把独立安装的 LLVM 放到 PATH 首位，确保 clang-cl 和 clangd 始终命中同一份工具链。

    2 配置一个起步工程 #

    2.1 用 manifest 声明依赖 #

    工程根目录放 vcpkg.json、CMakePresets.json、CMakeUserPresets.json（不提交到 Git）、CMakeLists.txt 和 .clangd。另建 triplets/ 放 vcpkg 配置，源码和着色器各用一个文件。

    vcpkg.json

    json
    {
  "name": "occt-lab",
  "version-string": "0.1.0",
  "builtin-baseline": "99541cc939bf01ae3c42f928266d648f5acb88fd",
  "dependencies": [
    {
      "name": "opencascade",
      "default-features": false
    },
    {
      "name": "sdl3",
      "features": ["vulkan"]
    },
    {
      "name": "imgui",
      "features": ["sdl3-binding", "vulkan-binding", "docking-experimental"]
    },
    "vulkan",
    {
      "name": "shader-slang",
      "host": true
    }
  ],
  "features": {
    "validation-layers": {
      "description": "Provide the Vulkan validation layer for local debugging",
      "dependencies": ["vulkan-validationlayers"]
    }
  }
}

    builtin-baseline 固定 port 的版本基准。SDL3 启用 Vulkan 支持，ImGui 启用 SDL3 和 Vulkan 后端以及 docking。shader-slang 声明为 host 依赖，因为构建时需要在本机执行 slangc。validation-layers 留作可选 feature，下面的 Release preset 使用默认配置。vcpkg 版本管理

    2.2 让 vcpkg 也用 clang-cl，只构建 Release #

    只在主项目里设置 CMAKE_CXX_COMPILER 时，vcpkg 仍会按所选 triplet 配置依赖。这里新增 triplets/x64-windows-clang-release.cmake，文件名去掉扩展名就是下一节要用的 triplet 名。

    cmake
    set(VCPKG_TARGET_ARCHITECTURE x64)
set(VCPKG_CRT_LINKAGE dynamic)
set(VCPKG_LIBRARY_LINKAGE dynamic)
set(VCPKG_BUILD_TYPE release)

set(VCPKG_ENV_PASSTHROUGH_UNTRACKED PATH)
set(ENV{CC} clang-cl.exe)
set(ENV{CXX} clang-cl.exe)
set(VCPKG_CMAKE_CONFIGURE_OPTIONS
    "-DCMAKE_C_COMPILER=clang-cl.exe"
    "-DCMAKE_CXX_COMPILER=clang-cl.exe"
    # cmcldeps forwards rc.exe's /c65001 option to clang-cl during dependency scanning.
    "-DCMAKE_NINJA_CMCLDEPS_RC=OFF"
)

if(PORT STREQUAL "opencascade")
    # Keep STEP and its dependencies for the plate import/export workflow.
    list(APPEND VCPKG_CMAKE_CONFIGURE_OPTIONS
        "-DUSE_OPENGL=OFF"
        "-DBUILD_MODULE_DataExchange=OFF"
        "-DBUILD_ADDITIONAL_TOOLKITS=TKDESTEP"
    )
endif()

    前四行选择 x64、动态 CRT、动态库和 Release 依赖。CC、CXX 以及传给 CMake port 的配置选项都指向 clang-cl.exe。VCPKG_ENV_PASSTHROUGH_UNTRACKED 把当前 PATH 传进 port 构建环境，PATH 字符串本身不计入 ABI。CMAKE_NINJA_CMCLDEPS_RC=OFF 处理的是 Windows 资源文件的依赖扫描：这套 Ninja 工具链里，cmcldeps 会把 rc.exe 的 /c65001 选项转交给 clang-cl。vcpkg triplet 变量

    最后一段只传给 opencascade。项目计划用 Vulkan 绘图，因此用 USE_OPENGL=OFF 跳过 TKOpenGl。数据交换预留 STEP 读写，关闭整组 DataExchange 后单独请求 TKDESTEP，OCCT 会补齐它依赖的工具包。manifest 里的 default-features: false 另外关闭了该 port 默认启用的 FreeType。OCCT 8.0.1 的工具包选择逻辑 · OCCT 的 OpenGL 开关

    2.3 用 CMakePresets.json 与 CMakeUserPresets.json 分离共享配置与本机路径 #

    仓库提交一份不含个人路径的 CMakePresets.json，只通过 $env{VCPKG_ROOT} 引用 vcpkg：

    json
    {
  "version": 3,
  "cmakeMinimumRequired": {
    "major": 4,
    "minor": 5,
    "patch": 0
  },
  "configurePresets": [
    {
      "name": "release",
      "displayName": "Release (clang-cl x64)",
      "generator": "Ninja",
      "binaryDir": "${sourceDir}/build-${presetName}",
      "architecture": { "value": "x64", "strategy": "external" },
      "toolset": { "value": "host=x64", "strategy": "external" },
      "toolchainFile": "$env{VCPKG_ROOT}/scripts/buildsystems/vcpkg.cmake",
      "cacheVariables": {
        "CMAKE_BUILD_TYPE": "Release",
        "CMAKE_C_COMPILER": "clang-cl.exe",
        "CMAKE_CXX_COMPILER": "clang-cl.exe",
        "CMAKE_EXPORT_COMPILE_COMMANDS": true,
        "VCPKG_OVERLAY_TRIPLETS": "${sourceDir}/triplets",
        "VCPKG_TARGET_TRIPLET": "x64-windows-clang-release",
        "VCPKG_HOST_TRIPLET": "x64-windows-clang-release"
      }
    }
  ],
  "buildPresets": [
    {
      "name": "release",
      "configurePreset": "release"
    }
  ],
  "testPresets": [
    {
      "name": "release",
      "configurePreset": "release",
      "output": { "outputOnFailure": true }
    }
  ]
}

    本机路径和缓存目录写在被 .gitignore 忽略的 CMakeUserPresets.json 中，继承上面的 release 预设：

    json
    {
  "version": 3,
  "configurePresets": [
    {
      "name": "release-local",
      "inherits": "release",
      "displayName": "Release with local vcpkg (clang-cl x64)",
      "binaryDir": "${sourceDir}/build-release",
      "environment": {
        "VCPKG_ROOT": "D:/vcpkg",
        "VCPKG_DOWNLOADS": "$env{VCPKG_ROOT}/downloads",
        "VCPKG_DEFAULT_BINARY_CACHE": "$env{VCPKG_ROOT}/archives",
        "X_VCPKG_REGISTRIES_CACHE": "$env{VCPKG_ROOT}/registries",
        "VCPKG_DISABLE_METRICS": "1"
      },
      "cacheVariables": {
        "VCPKG_INSTALL_OPTIONS": "--x-buildtrees-root=${sourceDir}/build-release/vcpkg_installed/vcpkg/blds;--x-packages-root=${sourceDir}/build-release/vcpkg_installed/vcpkg/pkgs"
      }
    }
  ],
  "buildPresets": [
    { "name": "release-local", "inherits": "release", "configurePreset": "release-local" }
  ],
  "testPresets": [
    { "name": "release-local", "inherits": "release", "configurePreset": "release-local" }
  ]
}

    这样配置有两个好处：

    1. 不必修改系统环境变量，也不向 %LOCALAPPDATA%\vcpkg 写入任何缓存；跨项目复用的 downloads、archives、registries 全都收口在 D:\vcpkg 下。
    2. 通过 VCPKG_INSTALL_OPTIONS 把构建中间目录 blds 和打包暂存目录 pkgs 留在项目自身的 build-release/vcpkg_installed/vcpkg/ 里，删除 build-release 就能把单项目的中间产物一并清干净，同时显式固定 binaryDir 为 build-release，与 .clangd 保持一致。CMake Presets 文档 · vcpkg 环境变量

    2.4 启用 import std;、import vulkan; 并编译着色器 #

    CMakeLists.txt

    cmake
    cmake_minimum_required(VERSION 4.5)
project(occt_lab LANGUAGES C CXX)

find_package(OpenCASCADE 8.0.1 CONFIG REQUIRED COMPONENTS FoundationClasses)
find_package(SDL3 3.4.20 CONFIG REQUIRED)
find_package(imgui CONFIG REQUIRED)
find_package(Vulkan 1.4.363 REQUIRED)
find_package(slang 2026.22 CONFIG REQUIRED)

set(CMAKE_CXX_EXTENSIONS OFF)
set(CMAKE_CXX_SCAN_FOR_MODULES ON)

add_executable(occt_lab src/main.cpp)
target_compile_features(occt_lab PRIVATE cxx_std_23)
target_sources(occt_lab PRIVATE
    FILE_SET vulkan_hpp TYPE CXX_MODULES
    BASE_DIRS "${Vulkan_INCLUDE_DIR}"
    FILES "${Vulkan_INCLUDE_DIR}/vulkan/vulkan.cppm"
)
target_link_libraries(occt_lab PRIVATE TKernel SDL3::SDL3 imgui::imgui Vulkan::Vulkan)
target_compile_definitions(occt_lab PRIVATE VULKAN_HPP_ENABLE_DYNAMIC_LOADER_TOOL=0)

set(triangle_shader "${CMAKE_CURRENT_SOURCE_DIR}/shaders/triangle.slang")
set(shader_output_dir "${CMAKE_CURRENT_BINARY_DIR}/shaders")
set(triangle_spv "${shader_output_dir}/triangle.vert.spv")

add_custom_command(
    OUTPUT "${triangle_spv}"
    COMMAND "${CMAKE_COMMAND}" -E make_directory "${shader_output_dir}"
    COMMAND "${SLANG_EXECUTABLE}" "${triangle_shader}"
        -entry vertexMain -target spirv -o "${triangle_spv}"
    DEPENDS "${triangle_shader}" "${SLANG_EXECUTABLE}"
    COMMENT "Compiling triangle.slang to SPIR-V"
    VERBATIM
)

add_custom_target(occt_lab_shaders DEPENDS "${triangle_spv}")
add_dependencies(occt_lab occt_lab_shaders)

    这里有两处 C++23 模块配置：

    • CMAKE_CXX_SCAN_FOR_MODULES ON 配合 cxx_std_23：CMake 4.5 会自动发现 MSVC 工具集里的标准库模块文件，并为 clang-cl 编译供 import std; 使用的 BMI。
    • FILE_SET vulkan_hpp TYPE CXX_MODULES：直接把 Vulkan-Hpp 随头文件附带的 vulkan/vulkan.cppm 加入目标，代码里即可 import vulkan;。同时定义 VULKAN_HPP_ENABLE_DYNAMIC_LOADER_TOOL=0，避免模块接口引入不必要的动态加载器封装。

    着色器仍交给 find_package(slang) 找到的 SLANG_EXECUTABLE，Ninja 根据 OUTPUT 和 DEPENDS 判断何时重新生成 triangle.vert.spv。Slang 命令行编译说明

    3 构建并接入编辑器 #

    3.1 打印版本并检查 SPIR-V #

    src/main.cpp

    cpp
    #include <Standard_Version.hxx>
#include <SDL3/SDL_version.h>
#include <imgui.h>

import std;
import vulkan;

auto main() -> int
{
    std::println("Library header versions");
    std::println("OCCT: {}", OCC_VERSION_COMPLETE);
    std::println("SDL3: {}.{}.{}", SDL_MAJOR_VERSION, SDL_MINOR_VERSION, SDL_MICRO_VERSION);
    std::println("Dear ImGui: {}", IMGUI_VERSION);
    std::println("Vulkan: {}.{}.{}",
                 vk::apiVersionMajor(vk::HeaderVersionComplete),
                 vk::apiVersionMinor(vk::HeaderVersionComplete),
                 vk::apiVersionPatch(vk::HeaderVersionComplete));

    return 0;
}

    shaders/triangle.slang

    hlsl
    static const float2 positions[3] = {
    float2(0.0, -0.5),
    float2(0.5, 0.5),
    float2(-0.5, 0.5),
};

[shader("vertex")]
float4 vertexMain(uint vertexIndex : SV_VertexID) : SV_Position
{
    return float4(positions[vertexIndex], 0.0, 1.0);
}

    在第 1.2 节的终端进入工程根目录，运行下面的命令。第一次 configure 时 vcpkg 会读取 manifest、恢复缓存或编译依赖，build 阶段再编译标准库模块、vulkan 模块、主程序和着色器。vcpkg CMake 集成

    powershell
    cmake --preset release-local
cmake --build --preset release-local
.\build-release\occt_lab.exe
Get-Item .\build-release\shaders\triangle.vert.spv | Select-Object Name, Length

    如果已经在终端中手动设置了 VCPKG_ROOT，也可以直接使用共享预设 release。依赖安装在 build-release/vcpkg_installed/x64-windows-clang-release，其中 tools/shader-slang 存放着色器编译器。

    3.2 VS Code 和 clangd 共用构建目录 #

    powershell
    code --install-extension ms-vscode.cmake-tools
code --install-extension llvm-vs-code-extensions.vscode-clangd
code .

    从刚才的开发者终端启动 VS Code，在命令面板执行 CMake: Select Configure Preset，选择 Release with local vcpkg (clang-cl x64)（release-local）。CMake Tools 会使用同一个 build-release。CMake Tools 的预设支持

    preset 已开启 CMAKE_EXPORT_COMPILE_COMMANDS。配置成功后，build-release/compile_commands.json 记录了每个源文件的编译器、头文件路径、模块参数和 C++ 标准。项目根目录的 .clangd 只需要指向它所在的目录。clangd 的编译数据库配置

    yaml
    CompileFlags:
  CompilationDatabase: build-release

    如果 VS Code 找到的是另一个版本的 clangd，在用户设置里指定本机路径：

    json
    {
  "clangd.path": "C:/Program Files/LLVM/bin/clangd.exe"
}

    4 排查 vcpkg 缓存未命中 #

    4.1 两个 PowerShell 版本带来的差异 #

    早期使用默认 x64-windows、分别配置 Debug 和 Release 时遇到过一次重编。两个构建使用相同的 baseline 和 triplet，第二次配置却显示 Restored 0 package(s)。对比 vcpkg-cmake 的 ABI 记录，CMake 都是 4.4.3，但最初的终端使用 PowerShell 7.7.0，另一个环境优先找到了 7.6.9。让重试进程先找到 7.7.0 后，vcpkg 从缓存恢复了全部 16 个包。

    vcpkg 用 ABI 哈希匹配二进制包。比较两次记录时，除了编译器、triplet 和 port 文件，也要看 PowerShell 等构建工具。这里的 CMake 版本是 vcpkg 构建依赖时实际调用的版本，可能与终端运行 cmake --version 看到的主项目入口不同。vcpkg 缓存排错文档

    4.2 在当前构建目录查 ABI 记录 #

    按第 2.3 节把 blds 定向到 build-release 后（以及使用 VS 自带只读 vcpkg 时），可以直接在构建目录内检查 port 记录的构建环境；如果独立 vcpkg 未传 --x-buildtrees-root，对应文件在 D:\vcpkg\buildtrees\opencascade\ 下。

    powershell
    $abi = '.\build-release\vcpkg_installed\vcpkg\blds\opencascade\x64-windows-clang-release.vcpkg_abi_info.txt'
Get-Content $abi | Select-String '^(cmake|powershell|triplet) '
Get-Command clang-cl, pwsh -All | Select-Object Name, Source

    5 缓存在哪里，怎样清理 #

    采用「独立克隆 D:\vcpkg + CMakeUserPresets.json 收口」后，单项目构建产物全部留在 build-release/ 内，跨项目共享的缓存全部留在 D:\vcpkg 内，%LOCALAPPDATA% 不会留下 vcpkg 文件。vcpkg 二进制缓存文档

    位置 保存内容
    build-release\vcpkg_installed\x64-windows-clang-release 当前项目使用的头文件、库、DLL 和 host 工具
    build-release\vcpkg_installed\vcpkg\blds port 的源码工作目录、构建日志和 ABI 信息（--x-buildtrees-root）
    build-release\vcpkg_installed\vcpkg\pkgs 打包暂存目录（--x-packages-root）
    D:\vcpkg\downloads 下载的归档与辅助工具（VCPKG_DOWNLOADS）
    D:\vcpkg\archives 可跨项目复用的二进制包（VCPKG_DEFAULT_BINARY_CACHE）
    D:\vcpkg\registries 注册表与版本信息缓存（X_VCPKG_REGISTRIES_CACHE）

    磁盘紧张时，先清理项目里的 blds 和 pkgs（等构建结束、需要的日志查完再删），或直接删除整个 build-release/。保留 D:\vcpkg\archives，以后重新配置或跨项目共用同一 triplet 时，ABI 匹配的 OCCT、SDL3 等依赖就能直接从缓存恢复；若完全不需要复用二进制包，可在 environment 中加 "VCPKG_FEATURE_FLAGS": "-binarycaching"。项目仓库只提交源码和共享配置，CMakeUserPresets.json、build-release/ 和 clangd 的 .cache/ 均加入 .gitignore。
