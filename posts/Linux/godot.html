    Ubuntu 从源码构建 Godot .NET，使用 Clang、Wayland 与 Rider

    更新于 2026-11-24

    一、准备依赖和源码 #

    本机使用 Ubuntu 26.10、GNOME Wayland 和 Radeon 880M，已有 Git、Python 3、build-essential、Clang 22、.NET SDK 11 和 Rider。构建 Godot 4.7.2 还需安装：

    bash
    sudo apt install --no-install-recommends scons pkgconf libwayland-bin lld
mkdir -p ~/src
git clone --filter=blob:none --branch 4.7.2-stable \
  https://github.com/godotengine/godot.git ~/src/godot
cd ~/src/godot

    保留默认的 Wayland 和 X11 后端。Godot 4.7.2 默认使用自带头文件，运行时加载系统库，这套配置可以省去 X11、Mesa 和音频库的开发包。libwayland-bin 提供 wayland-scanner，缺少它时构建脚本会关闭 Wayland 支持。Linux 构建检测源码

    二、用 Clang、lld 和 ThinLTO 编译 .NET 编辑器 #

    引擎主体按 x86-64-v3 编译。Godot 内置的 Embree 只编入部分求交实现，全局启用 AVX2 会导致链接时缺少 BVHN<4> 等符号。在 modules/raycast/SCsub 的 env_thirdparty = env_raycast.Clone() 后加两行，单独限制 Embree 的指令集：

    python
        env_thirdparty = env_raycast.Clone()
    if env["platform"] == "linuxbsd" and env["arch"] == "x86_64":
        env_thirdparty.Append(CXXFLAGS=["-march=x86-64-v2"])

    在源码根目录用 Bash 执行。module_mono_enabled=yes 是 Godot 4 启用 C# 的构建开关。target=editor 默认用 -O2，-j20 按本机的 20 个线程设置。

    bash
    build_args=(
  platform=linuxbsd target=editor module_mono_enabled=yes
  use_llvm=yes linker=lld lto=thin
  cflags=-march=x86-64-v3 cxxflags=-march=x86-64-v3
)
exe=godot.linuxbsd.editor.x86_64.llvm.mono

PATH="/usr/lib/llvm-22/bin:$PATH" scons "${build_args[@]}" -j20 &&
"./bin/$exe" --headless --generate-mono-glue modules/mono/glue &&
python3 modules/mono/build_scripts/build_assemblies.py --godot-output-dir=./bin

    三步分别生成原生编辑器、匹配该引擎的 C# API 绑定，以及 bin/GodotSharp/ 下的托管程序集。首次构建程序集时需要访问 NuGet。Godot .NET 构建文档

    为 clangd 生成编译数据库 #

    用 clangd 浏览引擎的 C++ 源码时，在刚才定义了 build_args 的 Bash 会话中运行以下命令。SCons 会把每个源文件的编译命令写入源码根目录的 compile_commands.json，写完即退出，无需重编引擎。

    bash
    cd ~/src/godot
PATH="/usr/lib/llvm-22/bin:$PATH" scons "${build_args[@]}" \
  compiledb=yes compiledb_gen_only=yes

    在启用了 clangd 的编辑器中打开 ~/src/godot，clangd 会从数据库读取头文件搜索路径和宏定义，按这次 Linux .NET 编辑器的配置索引 C++ 源码。数据库可以与第五节的 godot.sln 并存。切换目标平台或启用其他引擎模块后，用新的构建参数重新生成数据库。clangd 编译数据库说明

    三、安装到用户目录 #

    把可执行文件和 GodotSharp/ 放在同一版本目录，终端和 Rider 共用 ~/.local/bin/godot-dotnet：

    bash
    root="$HOME/.local/opt/godot-dotnet"
build=4.7.2-stable-clang-v3

mkdir -p "$root/$build" "$HOME/.local/bin" &&
cp -a "bin/$exe" bin/GodotSharp "$root/$build/" &&
ln -sfnT "$build" "$root/current" &&
ln -sfnT "$root/current/$exe" "$HOME/.local/bin/godot-dotnet"

    完成安装并创建示例项目后，用户目录里与 Godot 有关的路径如下：

    text
    ~/
├── src/godot/                            # 引擎源码
│   ├── godot.sln                         # Rider 的引擎解决方案
│   ├── compile_commands.json             # clangd 的编译数据库
│   └── bin/                              # 编译产物
│       ├── godot.linuxbsd.editor.x86_64.llvm.mono
│       ├── GodotSharp/
│       └── obj/                          # 增量编译用的目标文件
├── .local/
│   ├── bin/godot-dotnet -> ~/.local/opt/godot-dotnet/current/godot.linuxbsd.editor.x86_64.llvm.mono
│   └── opt/godot-dotnet/
│       ├── current -> 4.7.2-stable-clang-v3
│       └── 4.7.2-stable-clang-v3/        # 已安装的版本
│           ├── godot.linuxbsd.editor.x86_64.llvm.mono
│           └── GodotSharp/
└── RiderProjects/ForwardLab/             # 游戏项目
    ├── project.godot
    └── ForwardLab.sln                    # Rider 的游戏解决方案

    以后更新时，先保存 Embree 的本地补丁，切到新标签后检查是否仍需应用。重新编译并复制到新的 build 目录，切换 current 即可。回退到本文版本用 ln -sfnT 4.7.2-stable-clang-v3 "$root/current"。

    四、创建 Forward+ 项目，验证 Vulkan 和 C# #

    在新目录写入 project.godot，然后通过 Wayland 打开项目：

    bash
    mkdir -p ~/RiderProjects
project="$HOME/RiderProjects/ForwardLab"
mkdir "$project" &&
cat > "$project/project.godot" <<'EOF'
config_version=5

[application]
config/name="ForwardLab"
config/features=PackedStringArray("4.7", "Forward Plus")

[rendering]
renderer/rendering_method="forward_plus"
EOF

~/.local/bin/godot-dotnet --editor --display-driver wayland --path "$project"

    在左侧点 3D 场景，把根节点改名为 Main，按 Ctrl+S 保存为 Main.tscn。右键根节点，选 附加脚本 → C#，保存为 Main.cs。Godot 会同时生成 ForwardLab.csproj 和 ForwardLab.sln。

    csharp
    using Godot;

namespace ForwardLab;

public partial class Main : Node3D
{
    public override void _Ready()
    {
        GD.Print($"渲染器：{RenderingServer.GetCurrentRenderingMethod()}");
        GD.Print($"显卡：{RenderingServer.GetVideoAdapterName()}");
    }
}

    按 F6 运行当前场景，本机输出如下。首次按 F5 时选 当前场景，即可将 Main.tscn 设为项目入口。

    text
    Vulkan 1.4.354 - Forward+ - Using Device #0: AMD - AMD Radeon 880M Graphics (RADV STRIX1)

渲染器：forward_plus
显卡：AMD Radeon 880M Graphics (RADV STRIX1)

    单独启动 --project-manager 时看到 OpenGL 属正常情况。4.7.2 项目管理器默认使用 Compatibility，具体游戏使用的后端看游戏启动日志。项目管理器的渲染器选择

    五、在 Rider 里打开游戏和引擎源码 #

    • 写游戏。 在 Godot 的 编辑器 → 编辑器设置 → Dotnet → Editor → External Editor 选择 JetBrains Rider。本机自动识别到 /snap/rider/current/bin/rider.sh。在 Rider 打开 ~/RiderProjects/ForwardLab/ForwardLab.sln，用 Player 配置运行或调试。要让运行配置跟随引擎更新，可以复制一份 Player，将可执行文件设为 ~/.local/bin/godot-dotnet 展开后的绝对路径。
    • 顺手查引擎。 在 Rider 的 Explorer 右键游戏解决方案，选 Add → Existing Folder，附加 ~/src/godot。这样可以在游戏窗口里搜索 C++ 实现。
    • 开发引擎。 在源码根目录用与实际构建相同的参数生成引擎自己的 godot.sln，在 Rider 里选 editor | x64。以下命令复用第二节的 build_args，只生成工程文件。
    bash
    cd ~/src/godot
PATH="/usr/lib/llvm-22/bin:$PATH" scons "${build_args[@]}" \
  vsproj=yes vsproj_gen_only=yes
rider ~/src/godot/godot.sln

    如果已按 Rider 提示生成过工程，可以在上述 SCons 命令追加 vsproj_props_only=yes。检查 godot.linuxbsd.editor.x86_64.generated.props 里的 NMakeOutput，本次构建应指向 bin/godot.linuxbsd.editor.x86_64.llvm.mono。Godot 的 Rider 配置文档

    六、在命令行导出 Linux x86_64 游戏 #

    这里用同一台机器上完成的 C# 游戏 CoverMyShift 演示。Godot 导出时会用 Release 模板生成玩家启动的可执行文件，再打包场景、素材和 C# 程序集。模板按引擎版本安装一次，之后修改游戏只需重新导出。

    编译并安装 .NET Release 模板 #

    回到前面编译 4.7.2 编辑器的源码目录，把 SCons 目标设为 template_release，保留 Clang 和 C# 支持。本次模板构建使用以下参数：

    bash
    cd ~/src/godot
scons -j20 platform=linuxbsd target=template_release arch=x86_64 \
  module_mono_enabled=yes use_llvm=yes &&
install -Dm755 bin/godot.linuxbsd.template_release.x86_64.llvm.mono \
  "$HOME/.local/share/godot/export_templates/4.7.2.stable.mono/linux_release.x86_64"

    4.7.2.stable.mono 是这版 .NET 编辑器查找模板的子目录，linux_release.x86_64 是 Linux 导出器查找的文件名。也可以从 4.7.2 下载页 获取同版本的 .NET 导出模板。使用官方模板时，第二节编译编辑器用的 -march=x86-64-v3 不会传给玩家的可执行文件。

    配置导出预设 #

    在游戏的 project.godot 旁创建 export_presets.cfg。下面是本项目使用的预设；如果项目已有其他预设，追加时使用下一个编号，并同步修改 .options 的编号。

    ini
    [preset.0]

name="Linux x86_64"
platform="Linux"
runnable=true
export_filter="all_resources"
include_filter="Assets/Fonts/LICENSE-NotoSans.txt"
exclude_filter="Tests/*,Evidence/*"

[preset.0.options]

binary_format/architecture="x86_64"
texture_format/s3tc_bptc=true
dotnet/include_debug_symbols=false

    Linux x86_64 是稍后传给命令行的预设名。include_filter 把随游戏分发的 Noto Sans 字体许可加入资源包，exclude_filter 排除测试场景和验收录像所在的目录。换项目时按实际目录调整这两项。

    导出、压缩和试运行 #

    以下命令在项目外的 ~/RiderProjects/dist/ 生成游戏目录和压缩包。使用新导出目录时先用 mkdir -p 创建，--export-release 的最后一个参数要写到可执行文件名。

    bash
    cd ~/RiderProjects/CoverMyShift
out="$PWD/../dist/CoverMyShift-linux-x86_64"
mkdir -p "$out" &&
godot-dotnet --headless --path . --import &&
godot-dotnet --headless --path . --export-release "Linux x86_64" "$out/CoverMyShift" &&
tar -C "$(dirname "$out")" -czf "$out.tar.gz" "$(basename "$out")"

    本次生成的 CoverMyShift-linux-x86_64.tar.gz 约 59 MiB。解压后，同一目录里有可执行文件 CoverMyShift、资源包 CoverMyShift.pck 和 data_CoverMyShift_linuxbsd_x86_64/。最后一个目录含 CoverMyShift.dll 及 .NET 运行库，分发时保留这三项的相对位置。

    把压缩包解到临时目录，用无窗口模式启动了导出的游戏。运行下面两条命令后，终端输出 Godot 版本并正常退出：

    bash
    check_dir=$(mktemp -d)
tar -xzf "$out.tar.gz" -C "$check_dir" &&
"$check_dir/CoverMyShift-linux-x86_64/CoverMyShift" --headless --quit-after 5

    在桌面试玩时，直接运行 "$out/CoverMyShift" 即可。
